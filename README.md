# Gorgany Content Toolbox

Один інструмент на п'ять вкладок: **Річ-контент** — HTML для сторінки товару, **FAQ** — пара CMS-блоків, **Фото** — підготовка зображень із ZIP, **Градієнт** — затемнення знизу для банерів, **Таблиці** — розмірні таблиці для блоків Magento.

Білд не потрібен. Відкрий `index.html` у браузері або користуйся версією на GitHub Pages. Фото обробляються локально й нікуди не завантажуються.

## Файли

- `index.html` — розмітка всіх вкладок;
- `style.css` — спільні стилі;
- `script.js` — спільні хелпери, річ-контент, перемикання вкладок;
- `faq.js` — FAQ;
- `photo.js` — підготовка фото з ZIP;
- `gradient.js` — градієнт-оверлей;
- `table.js` — конструктор розмірних таблиць;
- `log.js` — черга логів і відправка в Google Sheets;
- `apps-script/Code.gs` — приймач на боці таблиці.

Спільні для всіх вкладок функції живуть у `script.js`: `$`, `g`, `esc`, `flashBtn`, `download`, `toggleSection`, `switchTab`, `activeTab`. `photo.js` і `gradient.js` — самодостатні IIFE, тому їхні внутрішні імена не конфліктують.

## Річ-контент

Збирає розмітку для поля Description товару (layout Rich Content 1). Результат — один HTML на три секції, вставляється цілком.

### Секція 1. Три зображення

Обери папку з фото у випадаючому списку. Список наповнює вкладка Фото: після завантаження архіву туди потрапляють слуги всіх погоджених товарів, згруповані за партіями, найновіші зверху. Папка `51. Куртка Salewa Ortles MED 3 RDS DWN Wms` у списку виглядає як `51_salewa_ortles_med_3_rds_dwn_wms`.

Назва фото збігається з назвою папки, тому посилання збираються самі за шаблоном:

```
https://www.gorgany.com/media/wysiwyg/all_rich/avto_added/{слуг}/{слуг}_left.jpg?format=webp
```

Список зберігається в localStorage браузера — останні 10 партій. Якщо слуг зʼявляється в новішій партії, зі старішої він прибирається, щоб не було дублів. Повторне завантаження архіву тієї ж партії оновлює її склад.

Суфікси для трьох фото — `_left`, `_middle`, `_right`. Якщо на фото є градієнт, увімкни перемикач — до суфікса додасться `_gradient`. `?format=webp` дописується завжди.

Для кожного фото:

- alt-текст — за замовчуванням First photo, Second photo, Third photo, можна змінити;
- заголовок і підпис — ліміти залежать від обраного режиму тексту.

| Режим | Заголовок | Підпис |
|-------|-----------|--------|
| 1 рядок | до 25 симв. | до 126 симв. |
| 2 рядки | до 50 симв. | до 80 симв. |
| Кастом | без ліміту | без ліміту |

Лічильники підсвічують наближення до ліміту й перевищення, але генерацію не блокують.

### Секція 2. Велике зображення

Використовує ту саму папку з суфіксом `_long`, без градієнта. Формат 1200 × 500. Alt за замовчуванням — Fourth photo.

### Секція 3. Опис і характеристики

Ліва колонка:

- заголовок H3 — назва товару або модель;
- короткий текст — видно до кнопки «Читати більше»;
- повний текст — розкривається після натискання;
- ключові параметри — заголовок блоку і до трьох пар «назва — значення». Якщо параметри не потрібні, вимкни «Включити в HTML».

Права колонка:

- Призначення й Особливості — заголовок і текст довільні. В Особливостях кожен рядок тексту стає окремим абзацом;
- Технічні характеристики — заголовок і текст під ним свої, таблиця характеристик підтягується на сайті автоматично;
- «Зроблено з любов'ю в Україні» — вимкни для неукраїнських брендів.

### Куди вставляти

1. Відкрий товар і в полі Layout обери Rich Content 1.
2. У полі Description увімкни Code view і встав згенерований код цілком.
3. Перевір, що працюєш у потрібному Channel + Locale (Akeneo) або Store View (Magento).

## FAQ

Генерує одразу два блоки: видимий HTML і мікророзмітку JSON-LD (Schema.org FAQPage). Тексти беруться з одних полів, тому збігаються до символу.

### Як користуватись

1. Впиши назву категорії, бренду або сторінки. Ідентифікатори згенеруються самі з транслітерацією: «жіночі куртки» дає `zhinochi-kurtky-faq-html` і `zhinochi-kurtky-faq-json`.
2. Заповни питання й відповіді. Новий рядок у відповіді — окремий абзац. Пара без питання або без відповіді в код не потрапляє.
3. Натисни «Згенерувати». У виводі два блоки: HTML з обов'язковим рядком `{{block ...}}` для акордеона в кінці та JSON-LD. Кожен копіюється своєю кнопкою.

Імпорт списком: перший рядок — питання, наступні — відповідь, пари розділені порожнім рядком. Можна додати до наявного списку або замінити його.

### Куди вставляти

Створи два CMS-блоки в Content → Elements → Blocks зі згенерованими ідентифікаторами і відповідним кодом. У випадаючих списках адмінки видно лише блоки з закінченнями `-faq-html` і `-faq-json`, тому ідентифікатори не змінюй.

Прив'язка до сторінки:

- категорії: Catalog → Categories → категорія → вкладка Content;
- бренди: Content → Layered Navigation → Brand Management → вкладка Page Content;
- кастомні сторінки: Content → Layered Navigation → Custom pages → вкладка Meta Tags;
- прокат: Stores → Configuration → Rental System → Rental System Settings → FAQ Settings.

Перед прив'язкою обери правильний Scope у лівому верхньому куті адмінки.

## Фото

Готує зображення під річ-контент із одного ZIP. Кожна папка в архіві — окремий товар, назва папки = назва товару.

### Номенклатура

У папці чотири файли з числовими іменами: `1`, `2`, `3` → квадрати, `4` → банер. Файли з нечисловими іменами ігноруються, якщо в папці є хоч один числовий.

Назва файлу на виході — `{slug}_суфікс.jpg`, де `{slug}` це латинська частина назви папки (кирилиця відкидається, пробіли → `_`, все малими). Якщо латиниці немає взагалі — назва транслітерується. Суфікси за номером фото: 1 → `left`, 2 → `middle`, 3 → `right`, 4 → `long`.

### Налаштування

| Параметр | Значення за замовчуванням |
|----------|---------------------------|
| Квадрат | 800 × 800 |
| Банер | 1600 × 800 |
| Якість JPG | 92 % |
| Суфікси | left, middle, right, long |
| Градієнт | старт 75 %, непрозорість 80 %, чорний |

Градієнт накладається **лише на квадрати**. Банер лишається без затемнення.

### Перегляд і погодження

Кожен товар показується окремо. Клік по фото переміщує центр кадру — кроп перераховується одразу. Кнопка під фото міняє роль (квадрат ↔ банер). Якщо в папці не чотири фото або банерів не рівно один, зверху зʼявляється попередження.

Гарячі клавіші: `←` `→` — навігація, `A` — погодити, `R` — відхилити.

У підсумку видно, скільки погоджено, відхилено й лишилось без рішення. В архів потрапляють **тільки погоджені** товари — і вони ж зʼявляються у випадаючому списку папок на вкладці Річ-контент. Список непогоджених папок можна скопіювати або зберегти в `.txt`.

### Лог у Google Sheets

Після завантаження архіву інструмент шле лог партії в Google-таблицю. **Рядок на кожен товар**, включно з відхиленими й тими, що лишились без рішення:

| Дата | Час | Партія | Товар | Слуг | Статус | Фото | Товарів у партії |
|------|-----|--------|-------|------|--------|------|------------------|
| 2026-08-27 | 14:32 | 2026-08-27 14:32:05 | Alpine Jacket Куртка | alpine_jacket | Погоджено | 4 | 12 |

Після кожної партії йде червоний рядок-розділювач на перші 20 стовпців. Він належить партії: при повторному завантаженні переїжджає разом з нею, а при відправці порціями стоїть лише після останньої.

Статуси: `Погоджено`, `Відхилено`, `Без рішення`. Кількість товарів у партії рахується зведеною таблицею по колонці «Партія», але продубльована в останній колонці, щоб не будувати зведену заради одного числа.

#### Налаштування один раз

1. Створи Google-таблицю. Extensions → Apps Script.
2. Встав вміст `apps-script/Code.gs`, збережи.
3. Deploy → New deployment → тип **Web app**. Execute as: **Me**. Who has access: **Anyone**.
4. Скопіюй URL виду `https://script.google.com/macros/s/…/exec`.
5. У вкладці Фото → секція 3 встав URL і натисни «Перевірити».

Аркуш `log` і шапка створяться самі при першому записі.

Адресу можна вставляти як завгодно — з кінцевим слешем, з пробілами, з `?`-хвостом або взагалі без `/exec`. Поле саме приводить її до правильного вигляду.

#### Як влаштована відправка

Apps Script відповідає через редирект на інший домен, тому браузер часто не дає прочитати відповідь на звичайний `fetch`. Через це «надіслав» і «записалось» — різні речі. Тому:

1. Дані йдуть звичайним POST.
2. Далі інструмент **перепитує таблицю через JSONP** (`<script>`-тег, на нього CORS не діє): скільки рядків з цим ідентифікатором партії насправді в аркуші.
3. Якщо нуль — той самий лог відправляється повторно через JSONP-GET, порціями приблизно по 1200 символів, і перевірка повторюється.

Бейдж «У таблиці» зʼявляється **лише після підтвердження від самої таблиці**. Якщо підтвердження немає — партія чесно лишається «У черзі».

#### Що варто знати

- **URL — це і є ключ доступу.** Хто його має, той може писати в таблицю. Тому він зберігається в localStorage браузера, а не в коді — у репозиторій нічого секретного не потрапляє. Кожен, хто користується інструментом, вставляє URL у себе один раз.
- **Повторне завантаження архіву оновлює партію, а не дублює її.** Скрипт спершу видаляє рядки з тим самим ідентифікатором партії, потім записує нові. Тобто можна повернутись до перегляду, змінити рішення, скачати архів ще раз — у таблиці буде актуальний стан.
- **Нічого не губиться при обриві звʼязку.** Лог спершу лягає в локальну чергу, і лише потім летить у таблицю. Якщо не долетів — партія лишається зі статусом «У черзі», кнопка «Надіслати те, що в черзі» дошле пізніше. Черга тримає останні 20 партій.
- Якщо URL не вказано взагалі, лог однаково пишеться локально й чекає, поки адресу додадуть.

#### Якщо рядки не зʼявляються

- **Після зміни `Code.gs` обовʼязково новий деплой.** Save в редакторі не оновлює веб-застосунок. Deploy → Manage deployments → олівець → Version: **New version** → Deploy.
- **Who has access має бути `Anyone`.** Варіанти «Anyone with Google account» і доступ у межах домену вимагають авторизації, якої запит зі сторінки не має — скрипт тоді просто не виконується.
- Кнопка «Перевірити» тепер дає однозначну відповідь: або показує назву аркуша й кількість рядків (без розділювачів), або конкретно каже, що не так.

## Градієнт

Окремий інструмент для довільних фото: вертикальний градієнт знизу, щоб текст на банері читався. Приймає кілька файлів одразу, попередній перегляд оновлюється на льоту.

Завантажується або одне поточне фото, або всі як ZIP. До назви файлу додається суфікс `_gradient`.

## Таблиці

Конструктор розмірних таблиць. На виході один блок: `<style>` + `<div class="gt">…</div>`, який вставляється в Magento як є. Усі класи мають префікс `gt-`, глобальних правил немає, тому стилі не зачіпають решту сторінки.

Вигляд повторює старий шаблон `сustom-tables` один в один: ті самі теги (`div`, `hr`, `iframe`, `table`/`td`), розміри шрифтів (заголовок 26px, підзаголовок 18px, текст крою 20px, таблиця 16px → 12px на ≤767px), фото крою 180/150 px, відео 700×500. Звірено рендером обох версій у Chromium: на ширині від 1000px результат збігається піксель у піксель, блок над таблицею — на всіх ширинах. Єдина свідома відмінність — вузькі екрани, де таблиця ширша за екран: старий шаблон обрізав першу колонку («Довжина ноги (від та…»), тут вона закріплена (`position: sticky`) і видна повністю, а решта скролиться.

### Шапка

- **Заголовок** — `h2.gt-title`.
- **Крій (Fit)** — чекбокс «Потрібен блок крою». Для кожного з чотирьох кроїв: «Показувати» і «Основний». Фото основного 180×180, решти 150×150 (атрибутами, як у шаблоні). Шляхи до фото фіксовані й підставляються через `{{media url="…"}}`. Опис основного крою підставляється автоматично й редагується.
- **Відео-гайд** — чекбокс і випадайка. Список відео лежить на початку `table.js` у масиві `GT_VIDEOS` (`id` з YouTube + назва); генератор сам будує посилання `youtube.com/embed/<id>`.

### Редактор таблиці

- Кількість рядків і колонок задається полями; вміст при зміні розміру зберігається.
- Виділення: клік, протягування мишкою або Shift+клік. Обʼєднання, якщо зачепити частину, розширює виділення автоматично.
- **Обʼєднати / Розʼєднати** — `rowspan`/`colspan`; текст обʼєднаних клітинок склеюється.
- Кнопки **B / I / U, Розмір, вирівнювання, Фон** діють на всі виділені клітинки. Якщо всередині клітинки виділено фрагмент тексту, B / I / U форматують лише його (так само Ctrl+B / I / U).
- **+/− рядок, +/− колонка** — відносно виділення.
- Таблицю з Excel чи Google Sheets можна вставити в будь-яку клітинку — вона розкладеться по сітці, сітка за потреби розшириться.
- «Закріпити першу колонку» робить її `position: sticky` під час горизонтального скролу; «Вертикальні лінії» — тонкі роздільники колонок. Перший рядок і перша колонка за замовчуванням жирні, як у шаблоні; це звичайне форматування, його можна зняти.
- Таблиць може бути кілька (жіночі, чоловічі…): кожна має підзаголовок `h3`, примітку під собою, кнопки переміщення, дублювання й видалення.

### Прев'ю і код

Прев'ю й код оновлюються на льоту. Прев'ю імітує базові стилі Magento (шрифт 14px, `img { max-width: 100% }`) і перемикається між десктопом і мобільним (375 px), щоб перевірити скрол. Чернетка зберігається в браузері; «Копіювати» кладе код у буфер і додає таблицю в історію (пʼять останніх, клік відкриває її в редакторі). «Приклад Salewa» завантажує жіночу таблицю Salewa для перевірки.

## Історія

Вкладки Річ-контент, FAQ і Таблиці зберігають останні пʼять генерацій у localStorage браузера. Клік по назві завантажує код у вивід, кнопки поруч копіюють одразу. «Очистити» видаляє історію вкладки. Активна вкладка теж запамʼятовується.
